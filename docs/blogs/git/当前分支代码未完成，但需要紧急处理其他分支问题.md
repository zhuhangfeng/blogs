# 当前分支代码未完成，但需要紧急处理其他分支问题
 

## 核心思路：先妥善保存当前分支的修改状态，再切换到目标分支处理问题，处理完再恢复到原分支的工作
## 具体操作步骤：
### 方案一：使用 git stash（推荐，临时保存未提交的修改）
git stash 可以把当前工作区、暂存区的所有修改「暂存」起来，让工作区回到干净状态，方便你切换分支。处理完其他分支后，再恢复这些修改。

1. 保存当前分支的修改状态：

```
git stash save "当前分支代码未完成，但需要紧急处理其他分支问题"
```
执行后，工作区会回到最近一次提交的干净状态，修改被临时存到Git的stash栈中。

2. 切换到目标分支处理问题：
```
git checkout 目标分支名
```
3. 处理完后，提交、合并
```
# 修改代码后，添加到暂存区
git add .
# 提交修改
git commit -m "修复master分支：XX功能的XXX问题"
# 合并回主分支（如果是hotfix分支）
git checkout master
git merge hotfix/master-bug-xxx
# 推送远程（可选）
git push origin master
```
4. 恢复到原分支的工作：
```
git checkout 当前分支名
```
5. 弹出stash栈中的修改：
```
git stash pop
```
执行后，stash栈中的修改会恢复到工作区，但不会删除stash栈中的记录。

### 方案二：直接提交「临时提交」（适合修改较多、暂存怕丢失的场景）
1. 在当前分支提交临时修改
```
git commit -m "当前分支代码未完成，但需要紧急处理其他分支问题"
```
2. 切换到目标分支处理问题
```
git checkout 目标分支名
```
3. 处理完后，提交、合并
```
# 修改代码后，添加到暂存区
git add .
# 提交修改
git commit -m "修复master分支：XX功能的XXX问题"
# 合并回主分支（如果是hotfix分支）
git checkout master
git merge hotfix/master-bug-xxx
# 推送远程（可选）
git push origin master
```
4. 恢复到原分支的工作
```
git checkout 当前分支名
```
5. 删除临时提交
```
git reset --hard HEAD^
```
